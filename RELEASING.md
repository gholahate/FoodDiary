# Выпуск версий через GitHub

Как всё устроено:

1. Код хранится в публичном репозитории GitHub.
2. При каждой отправке кода GitHub сам проверяет, что проект собирается (вкладка **Actions**, «Проверка сборки»).
3. Когда на сайте публикуется **Release** с тегом `vX.Y.Z`, GitHub собирает подписанный APK и прикладывает его к
   релизу (сценарий «Выпуск»).
4. Приложение (с версии, где появится проверка обновлений) находит новый релиз и предлагает установить его поверх.

Ниже — разовая настройка (шаги 1–4) и обычный цикл выпуска (шаг 5).

---

## Шаг 1. Ключ подписи (один раз, навсегда)

Рабочая версия приложения подписывается **вашим собственным ключом**. Android ставит обновление поверх, только если
оно подписано тем же ключом.

> ⚠️ **Если ключ или пароль потерять, обновлять приложение поверх станет невозможно никогда** — только удаление,
> установка заново и восстановление из резервной копии. Сохраните файл ключа и пароль **в двух местах** (например,
> менеджер паролей + облако). В репозиторий ключ не кладётся (`.gitignore` это запрещает).

В **Terminal** на Mac:

```bash
export JAVA_HOME="/Users/esviridov/Library/Android/sdk/jdk-21.0.12.1+1/Contents/Home"
"$JAVA_HOME/bin/keytool" -genkeypair -v \
  -keystore ~/FoodDiary-release.jks \
  -alias fooddiary \
  -keyalg RSA -keysize 4096 -validity 36500 \
  -storetype PKCS12
```

- Программа спросит пароль (дважды) — придумайте надёжный и запишите. У этого типа ключа пароль хранилища и пароль
  ключа **одинаковые**.
- Затем вопросы «имя, организация, город…» — можно ответить как угодно (например, имя и `RU`), в конце `yes`.
- Результат — файл `~/FoodDiary-release.jks` в домашней папке. **Сразу сделайте его копию** в надёжное место.

## Шаг 2. Репозиторий на GitHub

1. Android Studio → **Settings → Version Control → GitHub** → «+» → **Log In via GitHub…** → подтвердить в браузере.
2. Распакуйте архив проекта в новую папку (например, `~/Documents/FoodApp/FoodDiary-git`) и откройте её в Studio.
3. Меню **Git → GitHub → Share Project on GitHub** (если меню Git нет — **VCS → Share Project on GitHub**):
   - Repository name: `FoodDiary`;
   - **Private — снять галочку** (репозиторий публичный: так приложение сможет проверять обновления без пароля);
   - **Share**.
4. Studio покажет список файлов для первой отправки. Проверьте, что в нём **нет** `local.properties` и `*.jks`
   (их и не должно быть — их скрывает `.gitignore`). Нажмите **Add**.
5. На github.com откройте репозиторий → вкладка **Actions**. Через 5–10 минут «Проверка сборки» должна стать
   зелёной ✅. Если красная ❌ — откройте её, нажмите на красный шаг и пришлите текст ошибки.

## Шаг 3. Секреты для подписи

GitHub хранит их зашифрованными и подставляет только во время сборки.

1. Скопировать ключ в буфер обмена в текстовом виде (Terminal):
   ```bash
   base64 -i ~/FoodDiary-release.jks | pbcopy
   ```
2. На github.com: репозиторий → **Settings → Secrets and variables → Actions → New repository secret**.
   Создать четыре секрета (имя — точно как написано):

   | Name | Secret |
   |---|---|
   | `KEYSTORE_BASE64` | вставить из буфера (⌘V) — длинная строка |
   | `KEYSTORE_PASSWORD` | пароль из шага 1 |
   | `KEY_ALIAS` | `fooddiary` |
   | `KEY_PASSWORD` | тот же пароль из шага 1 |

## Шаг 4. Первый выпуск и разовый переход на рабочую версию

### 4.1. Выпустить 0.6.0

1. github.com → репозиторий → справа **Releases → Create a new release**.
2. **Choose a tag** → ввести `v0.6.0` → **Create new tag: v0.6.0 on publish**.
3. Title: `0.6.0`. В описании — что нового (это потом покажет приложение).
4. **Publish release**.
5. Вкладка **Actions** → «Выпуск» должен стать зелёным. После этого на странице релиза появятся
   `FoodDiary-0.6.0.apk`, `.sha256` и `version.json`.

### 4.2. Перейти с тестовой сборки на рабочую (один раз)

Сейчас на телефоне стоит сборка из Android Studio, подписанная ключом компьютера. Рабочая версия подписана новым
ключом, поэтому поставить её поверх нельзя — **один раз** придётся удалить старое приложение. Данные переносим через
резервную копию. **Строго по порядку, ничего не удалять раньше шага «Удалить»:**

**Вариант А — копия из самого приложения (проще).**

1. В `gradle.properties` временно сделать строку пустой: `debugAppIdSuffix=` (так тестовая сборка встанет поверх
   старого приложения, а не рядом).
2. Подключить телефон и нажать **Run** в Studio.
   - Если установка прошла — дальше п. 3.
   - Если ошибка `INSTALL_FAILED_UPDATE_INCOMPATIBLE` / «подпись не совпадает» — **ничего не удалять**, перейти к
     варианту Б.
3. В приложении: **Настройки → Резервная копия → Сохранить копию** → выбрать «Загрузки». Для надёжности ещё
   отправить этот файл себе в Telegram («Избранное»).
4. Вернуть в `gradle.properties` строку `debugAppIdSuffix=.debug`.
5. **Удалить** приложение «Дневник питания» с телефона.
6. На телефоне открыть страницу релиза (github.com/…/FoodDiary/releases) → скачать `FoodDiary-0.6.0.apk` →
   открыть. Android попросит разрешить установку из браузера → разрешить. Play Protect может предупредить о
   неизвестном разработчике → «Всё равно установить».
7. Открыть приложение → **Настройки → Резервная копия → Восстановить** → выбрать файл из «Загрузок» →
   проверить, что написано в окне (число продуктов и записей) → **Заменить**. Приложение перезапустится.
8. Проверить «Историю», базу продуктов, профиль.

**Вариант Б — копия через adb (если вариант А не встал поверх).** В Terminal на Mac, телефон подключён:

```bash
ADB=~/Library/Android/sdk/platform-tools/adb
mkdir -p ~/FoodDiary-copy && cd ~/FoodDiary-copy
$ADB exec-out run-as com.fooddiary.android cat databases/fooddiary.db     > fooddiary.db
$ADB exec-out run-as com.fooddiary.android cat databases/fooddiary.db-wal > fooddiary.db-wal
$ADB exec-out run-as com.fooddiary.android cat databases/fooddiary.db-shm > fooddiary.db-shm
# собрать всё в один файл и проверить, что данные на месте (должны быть числа, не ошибка):
sqlite3 fooddiary.db "PRAGMA wal_checkpoint(TRUNCATE);"
sqlite3 fooddiary.db "SELECT COUNT(*) FROM Product; SELECT COUNT(*) FROM DiaryEntry;"
# положить файл на телефон в «Загрузки»:
$ADB push fooddiary.db /sdcard/Download/fooddiary.db
```

Если на строках `-wal`/`-shm` будет сообщение «No such file» — это нормально. Затем пункты 5–8 варианта А
(при восстановлении выбрать `fooddiary.db`). Папку `~/FoodDiary-copy` не удалять, пока не убедитесь, что всё
перенеслось.

После перехода тестовые сборки из Studio ставятся **отдельным** приложением «Дневник (debug)» со своей пустой базой
и рабочий дневник не трогают.

## Шаг 5. Обычный цикл выпуска

1. Claude присылает архив; номер версии в `gradle.properties` уже повышен (`appVersionName`, `appVersionCode`).
2. В папке репозитория удалить **всё, кроме скрытой папки `.git`** (в Finder: ⌘⇧. показывает скрытые), и
   распаковать туда новый архив.
3. Studio: **Commit** (окно покажет изменённые файлы; написать коротко, что изменилось) → **Push**.
4. Дождаться зелёной «Проверки сборки» в Actions. Проверить тестовую версию «Дневник (debug)» на телефоне.
5. Создать Release с тегом `v` + версия (например `v0.6.1`), описать изменения → **Publish**.
   Если тег не совпадёт с `appVersionName`, «Выпуск» остановится с понятной ошибкой — ничего страшного,
   удалите релиз и создайте с правильным тегом.

### Как приложение получает обновление (с версии 0.6.1)

- При запуске, не чаще раза в сутки (выключается в «Настройки → О приложении»), и по кнопке «Проверить
  обновления» приложение читает `version.json` последнего опубликованного релиза.
- Если там версия новее — окно «Доступна версия X» с текстом из описания релиза: **Обновить** / **Позже**
  («Позже» — не напоминать сутки об этой версии).
- «Обновить»: скачивание с прогрессом → проверка контрольной суммы → автоматическая копия базы во внутреннюю
  папку → системное окно Android «Обновить приложение?» → подтвердить. Данные сохраняются.
- В первый раз Android попросит разрешить «Установку из этого источника» для Дневника питания — приложение
  само откроет нужный экран; включить, вернуться и нажать «Обновить» ещё раз.
- После установки приложение закрывается — откройте его снова.
- Версия 0.6.1 — первая с этим механизмом, поэтому **её один раз ставят вручную** со страницы релиза (поверх,
  без удаления: ключ тот же).

### Схема номеров

| appVersionName | appVersionCode |
|---|---|
| 0.6.0 | 600 |
| 0.6.1 | 601 |
| 0.7.0 | 700 |
| 1.0.0 | 10000 |

`appVersionCode` всегда только растёт — Android и проверка обновлений сравнивают именно его.

### Локальная сборка рабочей версии (необязательно)

Создать в корне проекта файл `keystore.properties` (в git не попадает):

```
storeFile=/Users/esviridov/FoodDiary-release.jks
storePassword=ваш_пароль
keyAlias=fooddiary
keyPassword=ваш_пароль
```

и выполнить `./gradlew :androidApp:assembleRelease` — APK будет в `androidApp/build/outputs/apk/release/`.
